# 汎用CSVマップ

決まった形のCSVを用意すると、OpenStreetMap ベースの地図に店舗などのピンを並べて公開できる静的サイトです。住所から緯度経度への変換はビルドのときに行い、結果はキャッシュしてリポジトリに保存します。

- 地図の描画：MapLibre GL JS（背景地図は OpenFreeMap）
- 住所 → 緯度経度：国土地理院の住所検索
- サーバーやデータベースは使いません。`dist/` を静的ファイルとして置けば動きます。

## 必要なもの

- Node.js 22.18 以上（TypeScript のスクリプトをそのまま実行するため）

```sh
npm install
```

## よく使うコマンド

| コマンド | すること |
| --- | --- |
| `npm run build:data -- <slug>` | 地図1つ分のデータを作る（CSVの取得 → 正規化 → 緯度経度の付与 → `dist/<slug>/`） |
| `npm run build` | すべての地図のデータを作り、ビューアもビルドする（公開用一式が `dist/` にできる） |
| `npm run dev` | 開発サーバー。先に `build:data` を実行し、`http://localhost:5173/<slug>/` を開く |
| `npm test` | 単体テスト |
| `npm run typecheck` | 型チェック |
| `npm run ogp -- <slug>` | SNSで共有されたときの画像（`maps/<slug>/ogp.png`、1200×630）を作る。Chrome を使う |
| `npm run update:municipalities` | 判定に使う市区町村一覧を国土地理院から取り直す（市町村合併があったとき） |

`build:data` に `--retry-unresolved` を付けると、前回位置が得られなかった住所を問い合わせ直します。

## 地図を足す

`maps/<slug>/map.config.json` を置くだけで、コードを変えずに地図が1つ増えます。`<slug>` が公開URLのフォルダ名になります。

```jsonc
{
  "title": "地図のタイトル",
  "source": { "url": "https://.../export?format=csv" },   // または { "path": "data.csv" }（このフォルダからの相対パス）
  "columns": { "name": "店舗名", "address": "住所", "category": "市町村" },
  "categoryLabel": "市町村",                 // 絞り込みの見出し。省略時は「カテゴリ」
  "geocode": {
    "prefix": "奈良県",                       // 住所に都道府県がないときに補う
    "bounds": [[135.5, 33.8], [136.3, 34.8]]  // この範囲外の結果は採用しない [[西, 南], [東, 北]]
  },
  "notice": "初回表示と情報画面に出す注意書き",
  "description": "検索結果やSNSに出す説明",      // 省略時は notice
  "sourceLabel": "出典の表記",
  "sourceUrl": "https://出典のページ",
  "styleUrl": "https://tiles.openfreemap.org/styles/liberty",  // 省略可
  "initialView": { "center": [135.8, 34.5], "zoom": 9 },      // 省略時はデータ全体が収まる範囲
  "areaPage": {                               // 省略するとカテゴリ別の一覧ページを作らない
    "title": "{category}の店舗一覧（{count}店）",   // {category} と {count} を置き換える
    "description": "{category}にある{count}店の一覧",
    "indexTitle": "カテゴリ別の店舗一覧",
    "indexDescription": "{count}店をカテゴリごとにまとめた一覧"
  },
  "ogp": { "lines": ["OGP画像に載せる一言", "2行まで"] }        // npm run ogp で使う
}
```

### サイト全体の設定（`site.config.json`）

```json
{
  "rootMap": "nara-otoku-2026",
  "siteUrl": "https://nara-otoku-2026.crssrds.jp/",
  "publisher": { "name": "crossroads inc.", "url": "https://crssrds.jp/" }
}
```

- `rootMap`：サイトの直下（`/`）に置く地図。ほかの地図は `/<slug>/` に置く。省略すると、直下には地図の一覧が出る。
- `siteUrl`：公開URL。SNS向けのタグ（`og:image` など）は絶対URLが必要なので、これがないと画像を出さない。
- `publisher`：運営者の名前とURL。構造化データに載せる。省略可。

ビルドのとき、各地図のページにタイトル、説明（`description`、なければ `notice`）、OGPのタグを書き込みます。情報画面の見出しと注意書きもHTMLに書き込んでおくので、JavaScriptを実行しない検索エンジンにも内容が伝わります。`maps/<slug>/ogp.png` があれば、それを共有用の画像として配置します。検索エンジン向けの構造化データ（JSON-LD）として、地図のページには `WebApplication`、一覧ページには `BreadcrumbList` と `CollectionPage`（何の一覧か、件数、データ作成日、出典）を入れます。店ごとの構造化データは、件数が多いとページが重くなるので入れません。

`areaPage` があれば、カテゴリ（`category` 列）ごとの店舗一覧を静的なHTMLで作ります。地図は JavaScript で描くので、店名や住所を検索エンジンに伝えるためのページです。置き場所は地図のページからの相対で `area/`（カテゴリの一覧）と `area/<カテゴリ>/`（店名・住所の一覧）で、地図のフッターと情報画面にリンクが出ます。各カテゴリのページの下には、ほかのカテゴリのページへのリンクを並べます。位置が特定できなかった店は載りません。

`siteUrl` があれば、検索エンジン向けに `robots.txt` と `sitemap.xml`（各地図のページ・一覧ページと、データを作った日）、AI向けのサイト案内 `llms.txt`（説明、注意書き、出典、各ページへのリンク）もサイトの直下に出力します。

存在しないURLを開いたときのページ（`404.html`）もサイトの直下に出力します。各地図とカテゴリ別の一覧へ案内し、検索結果には出しません（`noindex`）。どの階層のURLでも同じページが出るので、リンクは `siteUrl` のパス（なければ `/`）から始まる形で書きます。

### CSVの列

1行目は見出しです。列名は `columns` で対応づけるので、元のデータの列名を変える必要はありません。

| 項目 | 必須 | 用途 |
| --- | --- | --- |
| `name` | 必須 | ピンの名前、検索対象 |
| `address` | `lat`/`lng` がなければ必須 | 表示、検索対象、緯度経度の付与 |
| `lat` / `lng` | 任意 | あればそのまま使う |
| `category` | 任意 | 絞り込み（データに出てきた順に並ぶ） |
| `description` | 任意 | 吹き出しに表示 |
| `url` | 任意 | 吹き出しにリンク（http/https のみ） |

## 位置が得られなかった店を直す

`build:data` の最後に件数の内訳が出ます。位置が得られなかった行は、理由つきで `dist/<slug>/unresolved.csv` に書き出されます（公開はされません）。

直すには `maps/<slug>/overrides.csv` に行を足します。

```csv
name,address,lat,lng,approx,memo
,香芝市真美ケ丘6-10,34.54501,135.72438,,施設の位置
長次郎,,34.65,135.84,,名称だけで指定する例
,田原本町戎通174-1,34.55346,135.79073,1,おおよその位置として出す例
```

- `name` と `address` のどちらか（または両方）で一致させます。住所は建物名や表記の違い（`6-10` と `6－10` など）を吸収して比べます。
- `approx` に `1` を入れると、地図では白抜きのピンになり、吹き出しに「おおよその位置です」と出ます。
- `memo` など、ほかの列は無視されます。根拠のメモに使ってください。

### 位置の判定

国土地理院の住所検索が返した住所の細かさで判定します。

| 返ってきた住所 | 扱い |
| --- | --- |
| 番地・号まで（`…550番地`、`…3番11号`） | 正確な位置 |
| 町名や丁目まで | おおよその位置（白抜きのピン） |
| 市区町村まで、該当なし、範囲外、番地の食い違い | 未解決 |
| 入力に番地がない | 未解決（問い合わせない） |

問い合わせの結果は `maps/<slug>/geocode-cache.json` に保存してコミットします。判定は毎回やり直すので、判定のルールを変えても問い合わせ直す必要はありません。初回は1件あたり約1秒かかり、途中で止めても続きから再開できます。

## 公開（GitHub Pages）

`main` に push すると、`.github/workflows/deploy.yml` がテスト・ビルドして GitHub Pages に公開します。初回はリポジトリの Settings → Pages で、Source を「GitHub Actions」にしてください。

- ビルドのたびに CSV を取り直します。新しい住所があれば、Actions から国土地理院に問い合わせます。
- 未解決の一覧は、Actions の実行結果の成果物（unresolved）から取り出せます。
- サイトの直下は、地図が1つならその地図へ移動し、複数なら一覧を出します。

## 公開前に手で確認すること

画面の自動テストは入れていないので、見た目と操作は次の項目を手で確かめます。

- [ ] スマートフォンで開き、初回に注意書きが出る。「i」ボタンから出典と著作権表示を見られる
- [ ] 現在地ボタンを押すと、一覧が近い順になり、距離が出る
- [ ] 検索欄に店名や住所の一部を入れると、地図のピンと件数が絞られる
- [ ] 市町村（カテゴリ）で絞り込める
- [ ] クラスタをタップすると拡大する。同じ建物の店は一覧で全部見られる
- [ ] 吹き出しの「Googleマップで調べる」で、その店が開く
- [ ] URL をコピーして別のタブで開くと、同じ検索・同じ位置で開く
- [ ] キーボードだけで、検索、絞り込み、一覧の選択ができる（フォーカスが見える）

## 構成

```
maps/<slug>/          地図ごとの設定、キャッシュ、手動指定
scripts/              データ処理（build-data.ts）、全体のビルド（build.ts）
scripts/lib/          正規化（ビューアと共用）、ジオコーディング、市区町村一覧
src/                  ビューア（地図、検索、一覧、情報画面）
tests/                単体テスト
dist/                 出力（コミットしない）
```
